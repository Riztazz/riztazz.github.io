SmartTableDataTableModel.h

The model behind Set Data Table, and the stand-in a cell class is given for a row.

Source/SmartTables/Public/SmartTableDataTableModel.h

A table over a UDataTable, which is the other shape of data most projects already have.

A column binds to a field of the row struct by name. That lookup falls back to the authored name, which is the only reason a Blueprint row struct works at all: its fields carry an id on disk.

Rows are read where they sit, and no value is ever copied out. A row is known by its name, so a selection lives through rows being added to the asset.

The asset moved under this model: a row edited, added or dropped in the DataTable editor.

Values need nothing here, since rows are read where they sit. The row names do need reading again, and first: everything else in this class names a row by its place in that array.

The stand-ins go with them. One left naming a dropped row is a cell that stops reading, with nothing in the log saying why.

UnresolvedWarnings

What this model has already warned about, per column, and what that warning was about.

The value is a signature: both binding names, the path of the struct they failed against, and a hash of its field list. Warning again turns on whether that signature moved, and never on whether the column is still broken.

The field list is in there because a User Defined Struct is built again in place. It is the same object at the same path, carrying different fields. The path on its own would never move.

NoRowStructWarnedFor

The asset the no row struct warning was last given for. Empty until it has been given once.

That warning names an asset and never a column, so UnresolvedWarnings has no key for it. Resolving runs again on every edit to the asset, and with nothing kept here it would warn on each one.

USmartTableDataTableRow class

What a cell class is given for a DataTable row.

The table and the row name, and nothing else. Those two are what the built-in Get Data Table Row node takes, so a Blueprint cell over a DataTable is that node plus a pin.

One is built the first time something asks for the item of a row, and kept from then on. A CellClass column asks. A double click, the row menu and a query for the selected item all ask too.
