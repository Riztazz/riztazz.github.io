SmartTableCell.h

The class a cell Widget Blueprint sits on, and the two stock cells.

Source/SmartTables/Public/SmartTableCell.h

One cell, for a column that needs more than text.

Recycled, never rebuilt. The table keeps a pool and hands cells to new rows as the list scrolls, so OnCellAssigned runs many times on one instance. Whatever it sets on one row it sets again on the next. Whatever the cell holds is dropped in OnCellReleased. An item kept past a release stays alive as long as the table, and a delegate handle left bound fires for a row this cell stopped drawing.

OnItemSet has the shape of IUserObjectListEntry, so a UListView entry is already this class. A cell whose widgets bind to a viewmodel needs neither. It names an ItemSetter and holds no graph at all.

A function of this cell that takes the row's object, found by name.

Called with the item each time the cell is given a row whose item is a different object, before On Cell Assigned. Called with null as the cell goes back to the pool, after On Cell Released. A row whose item is the one handed last calls nothing, since the bindings a viewmodel feeds draw its changes.

A Manual viewmodel context adds a Set function for itself to the Widget Blueprint, and that function is what this names. It is found by name, so the plugin links no MVVM module.

An item of a class the setter does not take is handed over as null, and warned about once per class.

FindWidgetAnimation walks the class's property chain. A live feed asks for this one on every cell whose value moves, so that walk is what a table that flashes pays per change.

The name is the whole key. A widget's class never changes under it, and a graph built again in the editor gives new widgets instead of changing these.

USmartTableEditableCell class

The cell a column gets when its values are typed and not just read.

The model answers GetCellEditor and nothing here guesses: a text box, the same box aligned right for a number, or a checkbox. None draws the value as plain text, so a column of enums in an editable table stays readable instead of turning into a box that should not be typed into.

A value is written on Enter or on losing focus, never per character. A model that sorted again on every key would move the row out from under the cursor mid word. A refused value goes back to what the model still holds, with a Verbose line and no other mark. A redraw of its own row keeps the typing, and rows arriving or leaving above it end the edit with nothing written.
