SmartTableRowWidget.h

A widget wrapped around a whole row, so the row can animate in Sequencer.

Source/SmartTables/Public/SmartTableRowWidget.h

A widget wrapped around the cells of one row, so a row can be animated. Empty is the default.

Without one a row is plain Slate. SMultiColumnTableRow is no UObject and carries no animation list, so no UWidgetAnimation can bind to it and Sequencer has nothing to see. A cell needs none of this.

The cells go into a named slot of this wrapper, and HostColumns says which one. A wrapper with no named slot is dropped and its row draws unwrapped, with one warning per wrapper class.

ArrivalAnimation names an entrance and no code goes with it. Recycled like cells, so OnRowAssigned runs many times on one object and sets again everything it set last time.

Puts the cells of the row into the named slot of this wrapper.

A slot called Columns wins. Failing that, the only named slot is used whatever it is called, since a wrapper with one slot can mean nothing else by it.

False when there is no named slot, or several and none called Columns. It says so with a return and not a log, because the answer is the same once per table while this runs once per row.

On Row AssignedOnRowAssignedbp event
UFUNCTION( BlueprintImplementableEvent, Category = "Smart Tables|Row", meta = ( DisplayName = "On Row Assigned" ) ) void OnRowAssigned( ESmartTableAssignReason Reason )

Fires every time this wrapper is given a row, one it has drawn before too.

Reason is what sets the cases apart. A wrapper that plays its entrance whatever the reason plays it on every scroll, since scrolling is what hands a pooled wrapper its next row.

An entrance played from here needs a FlushAnimations straight after PlayAnimation. A row is built while the list draws, so this widget's tick for that frame has gone. Without the flush the wrapper draws once at rest and the animation reads only on the next tick, which draws as a row that shows, jumps, and then slides in.

Resolved ArrivalResolvedArrival
UPROPERTY( Transient ) TObjectPtr< UWidgetAnimation > ResolvedArrival
Transient
Never saved.

The animation named above, found once and held.

FindWidgetAnimation walks the class's property chain, and arming asks for this one on every row the table still owes an entrance.

The name is the whole key. A widget's class never changes under it, and a graph built again in the editor gives new widgets instead of changing these.

NAME_None in the pair here means the name has never been asked. That is also the answer for a widget naming no animation, and both want the same nothing back.
