A data table for UMG.

Columns are named once, in the Details panel or through SetColumns. A column binds by name to a property, or to a function that takes no input. Text, sorting and filtering all read that one binding. The header and the rows cannot end up reading different things.

Table->SetItems( Ships );
FSmartTableColumn Shield;             // a column that draws its own widget
Shield.ColumnId    = "Shield";
Shield.BindingName = "ShieldPercent";
Shield.CellClass   = UMyBarCell::StaticClass();

Most columns are one line and no code at all. A column with no CellClass gets the built-in text cell.

Rows arrive two ways. SetItems takes objects and builds a model inside the table. Everything else comes in through SetModel: a file, a server, a million rows.

The table itself never sorts. It says a sort was asked for and then draws whatever order the model hands back.

A cell was dropped onto another cell, and nothing has moved.

The table says what happened and the owner moves the data, the same way a sort works. A drop might mean a swap, a new row, or nothing at all, and only the owner knows which.

FCellWalkScope struct

Held by a row for as long as it is walking its own cells, so a header rebuild knows to wait.

Not part of the API. Only this plugin's own rows hold one, and it is public only because those rows are Slate widgets and not members of this class.

A scope, never a pair of calls. An early return, a throw, or a cell event that never comes back would each leave a plain flag set, and the header frozen for the life of the table. Two of them can sit inside each other, because it puts back what it found instead of clearing.
